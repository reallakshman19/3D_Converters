# EP-0005 — TASK-002/TASK-003 prework

## Exact-source diagnosis

1. Weight Match manual acceptance currently writes `config.overrides.rigidWeight[key]` directly. The consolidated final rigid review also writes its accepted values back into the same `rigidWeight` bucket. Stage identity is therefore lost.
2. `xmlCiiRigidWeightOverrideForNode` treats that single bucket as mapped authority before source XML Weight. Preview/run-parity and runner paths also contain direct reads of the same bucket.
3. The invocation builder supplies `--weight-scale 10` when kg→N compatibility conversion is enabled. Python `_build_rigid_payload` performs `_rigid_weight_for_edge(edge) * weight_scale` once. No JS-side ×10 was found in this traced path.
4. Therefore a persisted stale value such as `125` can be reintroduced as `125 kg` and then legitimately writer-scaled to `1250`, producing an apparent 100× symptom relative to a current intended `12.5 kg` without a double writer multiplication.
5. The empirical A1/A2 validator is explicitly read-only and uses strict `abs(deviation) > threshold`; exactly ±30% is within threshold. The standalone validation report currently renders an abnormalities table/report, but it does not provide per-row health badges in Weight Match/review rows.
6. The older subset validator popup is a different catalog/subset diagnostic and allows editing back into `rigidWeight`; it is not the A1/A2 empirical ±30% authority and can produce misleading “all-good” impressions when the relevant empirical scope is absent/skipped.
