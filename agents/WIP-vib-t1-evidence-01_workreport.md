## Authoring contract

New `tabs/vibration-integrity-identification-model.js` owns exactly these user-authored fields:

```text
mechanismId
line
caseId
canonicalId
assessmentUnitType
disposition
requiredQualification
sourceId
reason
```

All selections are explicit. `REQUIRED` requires an explicit governed qualification value. `NOT_APPLICABLE` / `UNRESOLVED` forbid a qualification value. Source ID and reason are mandatory. Unknown vocabulary is INVALID.

Seed objects with undeclared fields—including forged `rowId` or hidden authority fields—fail closed. Row identity is generated by the table model.

A non-empty row missing line/canonical scope identity is not silently ignored: it blocks evidence resolution until corrected/deleted.

## Exact scope custody

`resolveVibrationIdentificationEvidenceForScope()` selects exact `{line, caseId, canonicalId}` matches only. One invalid/incomplete matching row supplies zero positive evidence for that scope.

The shell resolves evidence separately for every rendered facility row and attaches records only for `status=READY` to a render-only row copy; FIT workspace/result state is not mutated.

The matrix adds an independent scope assertion. Both row-attached evidence and direct `context.mechanismIdentifications` must match the matrix row exactly or throw:

```text
MECHANISM_IDENTIFICATION_SCOPE_MISMATCH:<mechanismId>
```

Therefore wrong-scope `NOT_APPLICABLE` or REQUIRED evidence cannot influence another facility row even through an alternate direct matrix caller.
