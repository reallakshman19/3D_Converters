## Wire protocol (source facts only; NO R07 commit)

The host constructs a **real native isolated Worker** — `source-node-worker.mjs` via `node:worker_threads.Worker` or `source-browser-worker.mjs` via native browser `new Worker(url,{type:'module'})`. It sends a single message `{schema:'LFJ.CrossRuntimeSourcePort.v1',kind:'SCAN',jobId,sourceRefId,revision,blob,expectedSha256,pageEvents}` with a structured-cloned native Blob. Worker modules delegate to the same `scanSourceInsideWorker` and compute the R03 immutable original-byte SHA plus R04/R05 occurrence stream entirely inside the Worker; **no foreground JSON.parse, no fake READY/ACK-only worker**.

Each outbound `PROVISIONAL_PAGE` contains `sequence`, exact job/ref and original R05 event rows; its **entire JSON-wire message**, including metadata, is capped at **1 MiB**. R05 input batches are defensively capped at 64 events and split by UTF-8 wire bytes without dropping any source OPEN/SEAL events; the requested `pageEvents` is an upper count bound, not a justification for an oversized message. **At most one source event page may be unacknowledged**: host must stage the exact event page in its own transaction and return `{schema,kind:'PAGE_ACK',jobId,sourceRefId,sequence}` only after staging succeeds. The scan waits for this ACK before reading/emitting further pages, with a bounded 5-second timeout. Wrong/missing ACK rejects the scan with a typed source-port fault and cannot produce `SCAN_DONE`. `FAILED` may follow earlier provisional pages; the host must rollback staging, never interpret it as a valid empty or partial engineering result.

Only after full original JSON grammar and complete source event census does Worker send `SCAN_DONE` with `LFJ.JSON.OccurrenceIndexSummary.v1` (`complete:true`, `rightsBasis:SOURCE_FACTS_ONLY`, `engineeringReady:false`). This is **not** `LFJ.WorkerLifecycle.v1 SOURCE_INDEX_COMPLETE`: only the separate R07 transaction/verified R06 Worker byte receipt and caller-owned atomic commit may confer a committed source index, and even that grants **no engineering export rights**.

## Genuine cross-runtime verification

- Node22/24 independent `source-worker-port.test.mjs` launches a native WorkerThread entry (not an inline Worker-shaped object); compares source SHA to independent `node:crypto`, checks handwritten nested/escaped RFC6901 pointer census (seven OPEN+seven SEAL), original source replacement with equal byte length, malformed JSON refusal and no-ACK queue-pressure behavior.
- Actual hosted Chromium Playwright launches a **served ES module Worker** at `/lfj/ports/source-browser-worker.mjs`; compares Worker SHA to independent `window.crypto.subtle` **and** Node SHA and original pointer census. Source is served from exact PR checkout by a test-only HTTP server. This is genuine cross-runtime source-code behavior, but **not** the app's deployed `docs/lfj` tree.

## R06 → R07 → R08 → R09 committed source composition

`runCommittedSourceQuery` in `committed-worker-query.mjs` injects **two independent store ports**: a synchronous-commit R07 source-event index store (`stagePage/commit/abort/readOrdered`) and a R09 selected-result indexed store (`stagePage/commit/abort/readRange`). The **same** real Node/Chromium Worker must answer R06 `START`, actually consume bounded original byte pages, and run R03/R05 original JSON scanning inside Worker; only an accepted R06 receipt + complete matching R05 source census authorizes R07 `SOURCE_INDEX_COMPLETE`. After that, the genuine R08 selector stages R09 pages once and the caller reads by index offset with source/scope/job-fenced cursors. Failure or missing Worker/store aborts rather than falling back. The caller **must supply a live `getCurrentBasis` attestation** for source, SHA, revision, scope, and job; no fixed-basis default may silently publish a stale result. Tiny-array fixtures are not production persistence.
