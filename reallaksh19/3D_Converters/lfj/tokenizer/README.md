# LFJ R04 — bounded original-byte incremental JSON grammar (U01–U04 native qualified)

**Owner child:** [#1062](https://github.com/reallaksh19/3D_Converters/issues/1062); parent [#1042](https://github.com/reallaksh19/3D_Converters/issues/1042); released V3.2 claim C2_TOKENS=5/130, four separable 25%-weight units. **Four native units qualified at their exact direct Node22/24 heads: U01 escaped strings, U02 Unicode fidelity, U03 whole-document grammar and completed RootFacts, U04 resource/cancellation/real original-source bytes. This is NOT browser Worker, R05 original occurrence, downstream app or R18 release qualification.**

## Downstream-first source identity

This module imports no Preview/Weight code and never changes [GC-PW/1.0](https://github.com/reallaksh19/3D_Converters/blob/main/contracts/gc-pw-v1/contract.mjs) source IDs, `basisId`, Mode B XML order, physical source ordinals, `RigidMatch1`, `Rigidmatch2` or final CII mass. It reads R03 immutable original bytes, not a string length, filename, pointer into a cloned object or guessed engineering selection.

**Upstream:** R03 `LFJ.SourceSnapshot.v1`, including sync in-memory `readRange` and async Blob-backed `readRange`; both carry SHA and revision, and enforce <=1MiB page reads. Original bytes are never mutated and old revisions reject reads. R03 exact [Node 22/24 original 10.54MB source gate](https://github.com/reallaksh19/3D_Converters/actions/runs/37783551081) passed. R01 separately provides [AST-free token-derived RootFacts](https://github.com/reallaksh19/3D_Converters/pull/1053); R04 is not allowed to manufacture `complete:true` before **all** JSON grammar has been checked in U03.

## API implemented at U01

`createJsonByteCursor(snapshot,{startByte=0,pageBytes=65536,signal=null})` exposes `sourceSha256`, `sourceRevision`, `byteLength`, current `position`, `peek()`, `take()`. The cursor asynchronously reads a bounded original source range, over either synchronous or asynchronous R03 store. `pageBytes` is 1..1MiB. Operations reject invalid source/range, stale or closed R03 source, and AbortSignal cancellation with typed errors. Cursor position and scanner token spans are original UTF-8 byte offsets, never JS UTF-16 offsets.

`scanQuotedJsonString(cursor,{maxTokenBytes=65536})` consumes exactly one **quoted JSON string token**, returning immutable `{type:'string',startByte,endByteExclusive,value,sourceSha256,sourceRevision}`. It preserves even/odd backslash behavior, quotes, solidus, control escapes and bounded `\\uXXXX` escapes. Surrogate-pair escapes are decoded together; invalid escapes/control bytes, unclosed strings and malformed UTF-8 refuse typed errors. The scanner does NOT accept a whole JSON document or claim grammar is complete.

**No unbounded scalar copying:** token cannot exceed 1MiB, even if caller overrides the limit; default 64KiB. UTF-8 byte text is decoded only for one bounded scalar. `TextDecoder('utf-8',{fatal:true,ignoreBOM:true})` rejects malformed data while retaining legitimate U+FEFF characters inside a JSON string (file-level BOM policy remains U03). Node22/24 U02 independently exercises split multibyte bytes, escaped surrogate pairs, isolated surrogate negatives, malformed/overlong/truncated UTF8 and sync/async R03 backing.

## U03 complete JSON grammar — independently sourced native acceptance

`scanJsonDocument(snapshot,{pageBytes,maxTokenBytes,maxDepth,maxTokens,maxByteLength,onToken,signal})` consumes the exact R03 original-byte port as a bounded asynchronous grammar. It emits ordered token events `type,startByte,endByteExclusive,sourceRevision,sourceSha256` to an optional backpressured `onToken`; it never buffers a whole-document AST or uses `JSON.parse`. Validates object/array delimiters, quoted and escaped keys, numbers retaining **lexical decimal source** instead of rounding, booleans/null, separators, duplicate decoded keys (including escaped textual aliases), complete closure and exact EOF. Only after EOF emits shallow `lfj-token-root-facts/v1` with `complete:true`. A JSON-valid scalar root remains syntactically valid but **not an R01 qualified structured staging root**. [Independent grammar test](./json-tokenizer-grammar.test.mjs) covers real Blob and in-memory source, original-byte half-open spans, wrong numbers, duplicate keys, truncated JSON, top-level scalars and root envelope counts. [U03 hosted evidence on child #1062](https://github.com/reallaksh19/3D_Converters/issues/1062).

## U04 resource RED→GREEN and real source custody gate

The initial U04 source at blob `dd21b6938a84bfc7e512220541e0409841df5ad9` lacked a cap on the `raw` accumulation of **numeric scalars**, retained unlimited own keys per object in a `Set`, and could return `complete:true` after `SourceSnapshot.close()` while its last page was cached. The independent [RED test `json-tokenizer-resource-completion.test.mjs`](./json-tokenizer-resource-completion.test.mjs) was committed at `ab2a48526025667add1f21810b489e30fa593356`; [Node22/24 hosted RED #37790912096](https://github.com/reallaksh19/3D_Converters/actions/runs/37790912096) failed the five targeted claims (not just test-count statistics). Corrected at `0a5c853697ef3c724e1398a027f3168c30ce63b2`: numeric lexemes use same `maxTokenBytes` hard cap as strings; per-object keys max 8192, local original key bytes max 1MiB and simultaneously active nested key bytes max 4MiB with caller overrides checked; duplicate-key rejection remains fail-closed. Exact EOF now checks the original source revision and liveness even when the cursor still caches bytes.

[Exact native Node22/24 and real original-source workflow #37791074941](https://github.com/reallaksh19/3D_Converters/actions/runs/37791074941) **PASSED** for the patched candidate. Node24 real-source fixture is the original 10,539,386-byte `Benchmarks/Managejson to Input XML/ATTRIBUTE_managed_stage.json`, pinned SHA256 `e465fa696c80516868349032af6cf1976d9a180c86ea2a7b9eab28c6436fa92a`, expected bare-array root count 270; timing and heap change are measured but **not** accepted as an owner hardware SLO, and raw bytes are not independent XML/CII goldens. Protected maximum input is bounded, not a blanket guarantee that any arbitrarily large JSON is accepted.
