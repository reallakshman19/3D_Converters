## Product claim

The actual XML→CII 2019 Resolver must take the selected original JSON **File** + XML source + selected hierarchy/zone, produce the same complete XML semantic ledger that the existing legacy Resolver would produce **after selecting that top-level source population**, and export the unchanged Node-wise and Evidence Tree CSV formats. This is distinct from A1 original-source custody, A2 deployed-site/Worker closure, H10 research capsule, #141 independent protected full-ledger acceptance and downstream CII permission.

A3 T01/T02 safely fail closed for indexed non-ALL selection. **That refusal is correct for now, but does NOT satisfy selected-scope A3.U02/U03/U04.** T05 must replace refusal only after verifying this contract.

## Exact code contracts investigated

1. **Legacy scope selection:** `tabs/xml-cii-2019-standalone/xml-cii-json-hierarchy-scope.js::{buildJsonHierarchyScopeIndex,materializeJsonHierarchyScope}` indexes a root JSON array, or `children` of a root object, in top-level item order; it groups entries by scope label `OWNER_ZONE`, `ZONE_ID`, `OWNER_SITE`, `SITE`, `ZONE`, with special behavior for `SITE/ZONE/GROUP` containers (`name || ownerScope`). Label comparison is exact string equality, not fuzzy branch equality. `__UNSCOPED__` is a real selection; `__ALL__` is explicit all. A label may select **noncontiguous** top-level items in source order. Unknown labels throw. The current implementation obtains strings by regex over each item slice, so it **can read nested text**, not a structurally verified direct attribute: do not promote these heuristic labels as source authority without verifying the same top-level ownership semantics against bounded original slices and resolving ambiguity.
2. **Legacy matching:** `tabs/xml-cii-2019-standalone/xml-cii-resolver-json-trace.js::scopedStagedJsonInput` selects and materializes JSON **before** `buildStandaloneDtxrResolutionLedger(sourceText, selectedInput, ...)`. All XML nodes are parsed from original `sourceText`, not zone-pruned after matching. A nonmatching XML node is still present and can be `UNRESOLVED`; a negative match is legitimate only after complete input XML attestation/census.
3. **Legacy sequence/paths:** `tabs/xml-cii-2019-standalone/xml-cii-trace-resolution-ledger.js::walkStaged` increments `jsonSequence` for every visited stage object, branch containers included. If source items are filtered first, **result-visible** `$[0]`, `$[1]` paths and fallback `JsonNodeNo` sequence are based on that selected input. Explicit node aliases (`JsonNodeNo`, `NodeNumber`, etc.) remain their original values. Source **custody** still requires the immutable original global path/ordinal/byte span; these are two different identifiers and MUST NOT be conflated or silently used interchangeably. Cross-branch inherited position, bore, PS tags, POS coordinates and branch labels must be preserved.
4. **Current indexed catalogue:** `lfj/qualification/experiments/consumer-sparse-b0-query/paged-query.mjs` binds original `sourceSha256` + committed generation, exposes original byte spans/parent/ordinal and paged, bounded `ALL | RANGES | NONE` selections. Its ordinal is the original catalogue index, **not a filtered output path or local sequence**. Existing `branch-sliced-projection.mjs` enumerates all original root branches, derives original paths from parent ordinals, reads at most a **1MiB** original branch span at once, and builds a complete immutable source digest and page digests. It explicitly requires ALL source and root-array profile.
5. **Current indexed matching:** `lfj/qualification/experiments/consumer-sparse-b0-xml-match/xml-csv-parity.mjs` validates **the entire** committed projection (page and evidence hashes plus source ordinals), then reconstructs `$[n].children[m]` in original root index order and calls the **existing** `runStandaloneResolverJsonTrace`. It rejects nested non-leaf domain shape and missing/empty branches. It currently proves only flat root BRANCH + leaf consumers; it is not a native non-ALL product matcher. `xml-csv-original.html`, the research handoff and its `sourceOnly:true, engineeringReady:false, downloadAuthorized:false` flags do not grant product export.
6. **Current product receipt:** `tabs/xml-cii-2019-standalone/ui-adapted/xml-cii-adapted-lfj-indexed-export.js` binds the original JSON `File` object, exact source SHA, XML SHA, config, revision, whole original CSV digests and local consent. New selected-scope results require a scope-identity digest as an additional guarded input, not a second grant path. T01 has added scope to the UI revision and T02 denies unsupported indexed selection before Workers.

## Selection basis and data-model decision

Define **one immutable source-backed selection manifest** before any selected matching call:

| Property | Meaning / required invariants |
| --- | --- |
| `sourceSha256, sourceGeneration` | Original entire File bytes and committed source catalogue; never recompute identity from a selected fragment. |
| `xmlSha256` + `configDigest` | Exact original XML and resolved options used for DTXR; changes invalidate Build. |
| `requestedScopeId` | Exact explicit `__ALL__` or validated non-ALL label, including `__UNSCOPED__`; unknown and ambiguous labels fail closed. |
| `originalRootOrdinals` | Sorted **original** top-level object ordinals, verified directly against committed root-child structure; may be discontiguous; duplicates, unsorted, wrong parents and missing rows are invalid. |
| `originalRootPaths` | `$[originalRootIndex]` for every selected root, retained solely for source/provenance/tamper checks. |
| `selectedDisplayRootIndex` | Dense `0..N-1` order in selected legacy input. Display paths `$[localIndex].children[localChild]` must be related back to original paths one-to-one. |
| `selectedSequence` | Local `walkStaged` preorder for **only selected objects**, with source-explicit node numbers overriding fallback. Never substitute original-source `jsonSequence` if legacy selection semantics would differ. |
| `manifestDigest` | Canonical hash of the *complete* selected basis including ordered original root identities, XML/config and selection label, recomputed/checked at projection, matching, receipt and both CSV clicks. Untrusted caller-supplied digest alone does not authenticate a selection. |
| `sourceOnly` and `productAuthorization` | Research handoff stays source-only/unapproved; only the existing indexed receipt can authorize current local CSVs with opt-in. No CII engineering grant. |

**Structural admissibility:** T05 may initially support only original root **array** with nonempty flat BRANCH roots and proven leaf consumers. Original root-object `children` wrapper is supported by the *legacy text selector* but **NOT** currently supported by indexed source profile; reject with a typed `ROOT_PROFILE_UNSUPPORTED` instead of accidentally treating it as ALL. Empty selection, malformed/duplicate/mismatched original ordinals, nested component containers, unsupported root type, duplicate scope IDs carrying contradictory zone semantics, large branch spans, IDB page tampering and unavailable file/catalogue identity must fail closed. Do not relax the current **32MiB original input** cap or the research **8MiB UTF-8 capsule** cap.

## Smallest T05 engineering implementation seam — without redesign

1. In the existing source/projection boundary, enumerate committed original root-object catalogue rows and **boundedly** decode each root branch's source metadata (the existing <=1MiB slice bound). Classify admissible label, name, root type and original `path/ordinal`; compare against legacy hierarchy semantics on independently supplied fixtures. Reject roots with ambiguous ownership (including a nested-only `OWNER_ZONE` accidentally mistaken for a top-level zone) rather than silently assigning a false zone. Keep original source pages and generation intact.
2. Preserve the existing **ALL** projection and all existing unfiltered SHA/ledger/CSV goldens exactly. For explicit selected label, derive sorted selected original-root ordinals and a scope manifest. Do not select by branch label alone; labels need not be unique and compatibility matching between XML branch root and staged source is separate.
3. After full source HEAD/page checksum attestation, pass only permitted original facts to the existing matching reconstruction. Reconstruct **dense local roots and local preorder sequence**, retaining an additional original ordinal/path → local view mapping so every generated evidence member is traceable to original bytes. Assert selected fact/root/source-object completeness **relative to selected source**, while attesting the **full XML node census** against the unfiltered XML original. No filtering finished CSVs or changing geometry.
4. Capture both original CSVs with existing shipping serializers and existing #185 receipt/consent; bind `manifestDigest`, file revision and current XML/config/source to each generated receipt. In-flight source/selection/config/Worker changes, mismatched HEADs and per-click file rehash failure must block both downloads. Even a matched negative (all XML unresolved) requires valid complete ledger, not an empty success.
5. Explicit `__ALL__` remains the current known-good path and is a regression control. A staged legacy JSON string path remains separate and its selected semantics/CSV behavior must not be accidentally revised. T05 **must not** write into A1/A2/protected #141 modules without independently owned source authority.

## Oracle / regression matrix

**T04 tests** (unit characterization of current legacy behavior; not selected indexed acceptance): noncontiguous multi-root `ZONE-1` selection; `ZONE-2`; explicit ALL; unknown scope refusal; `__UNSCOPED__`; exact selected roots in order; local selected path + fallback sequence vs global original provenance; explicit node alias stable; root-object `children` wrapper recognized only by legacy; selected indexed Build **remains refused** until T05.

**T05 RED→GREEN acceptance:** source-backed original root path+ordinal mapping; at least one authentic non-ALL fixture with independently expected full XML ledger + exact two CSVs (not author-derived); discontiguous scope labels; no cross-zone facts; repeated-name/different-root branch; injected nested misleading `OWNER_ZONE`; empty/unknown selections; root wrapper and nested non-leaf typed denial; 32MiB+1 admission; mutation/stale/cancel/retry/cold restart and tampered page; same committed SHA and original CSVs across Node22/24 plus *real* Chromium user-facing controls. Keep real Owner 30MB original positive **NOT_RUN** until supplied and independently fingerprinted, and #141 protected acceptance separate.

## Owner-scope ambiguity (explicit, not a hidden simplification)

Legacy hierarchy labels are **not** the same as XML branch-selection `branchSelection`, and a scope restriction does not authorize omitting XML rows. If the Owner intends to **exclude XML nodes outside the selected zone** from trace and CSV, that is a **different product-output claim** from current legacy behavior, requiring an Owner choice and independent changed golden. This contract selects the **legacy-compatible full-XML-census interpretation** for implementation safety until instructed otherwise; it does not quietly overwrite protected output. Support for nested hierarchies, separate Owner-supplied positive 30/90MiB sources, and >32MiB product admission remain independent choices.
