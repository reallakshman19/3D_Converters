## U01 new Worker-only admission seam

`runRequiredWorkerJob({createWorker,trustedWorkerCtor,jobId,sourceRefId,sourceRevision,sourceSha256,byteLength})` requires an **actual platform-trusted Worker constructor** at the application composition root, not a same-thread Worker-shaped inline callback. The browser defaults to its native `globalThis.Worker`; Node WorkerThreads callers explicitly pass `trustedWorkerCtor: Worker` from `node:worker_threads`. Method-shape and echoed `READY` are insufficient; the created object must also be `instanceof` that trusted constructor. The constructor/`createWorker` injection is a **trusted application configuration boundary** and must never be built from untrusted source data; fake constructors supplied by an adversary are not an isolation guarantee. A missing/null/throwing factory rejects `WORKER_UNAVAILABLE`; a synchronous function posing as a Worker fails `INVALID_WORKER_PORT` **before postMessage is invoked**. The port must have asynchronous `message`/error subscription, `postMessage` and `terminate`; it supports browser Worker event listeners and Node WorkerThreads `on/off`. It sends versioned `LFJ.WorkerExecution.v1` `START`, receives matching `READY` with **the same job and source metadata** or fails `WORKER_PROTOCOL`; a hung admission times out rather than ever running JSON on the caller thread. On failed START/READY admission, R06 terminates the Worker before rejecting; on successful admission, caller retains Worker for source transfer. R07 governs later cancellation, retry, stale job and higher-level session disposal.

**Independent test proof:** [`required-worker.test.mjs`](./required-worker.test.mjs) committed first (RED until production `required-worker.mjs` added), plus real **native Node WorkerThreads fixture** `required-worker-fixture.mjs`. Tests assert actual `isMainThread===false` and `threadId>0` under an independently instantiated Worker, invalid source metadata fails before construction, unavailable factories and fake Worker shaped callbacks fail without inline work. [Exact Node 22/24 dedicated workflow #37801199693](https://github.com/reallaksh19/3D_Converters/actions/runs/37801199693) **PASSED both versions** at production + dedicated workflow head. This is actual Node Worker isolation in a native test, **not** a Chromium performance metric nor a universal assertion that any arbitrary injected port is truly isolated.

## U02 bounded original-source byte transport

`transferBoundedSourcePages({worker,trustedWorkerCtor,snapshot,jobId,sourceRefId,pageBytes,ackTimeoutMs})` requires a genuine isolated Worker instance, an attested immutable R03 snapshot, and distinct job, source-ref, original revision and SHA. It sends only **one transferable Uint8Array original source page at a time** with original `startByte`/`endByteExclusive`. It does not read or enqueue the next original page until a matching `SOURCE_ACK` attests the exact job/ref/revision/SHA/range and received byte count. Maximum page size is **65,536 bytes**, with a bounded timeout 1–30,000ms; missing ACK is typed `WORKER_ACK_TIMEOUT`, invalid ACK `WORKER_PROTOCOL`. One page outstanding bounds this port's source-payload pressure independent of total source size. This is not an entire browser heap or throughput guarantee.

The independent [U02 Node Worker test](./bounded-source-transfer.test.mjs) uses a **real** `worker_threads` receiver [fixture](./bounded-source-fixture.mjs), including delayed ACK and a no-ACK Worker. Its manually asserted 130,071-byte source requires eight 16,384-byte source reads, exact source offsets, max one unacknowledged page; the no-ACK Worker must observe just one source read before typed failure. The first RED commit `e2003f9` failed because the module was not implemented; the first production pass exposed a **test harness mistake** (unwrapped snapshot passed instead of the read-spy port), corrected at `9fc49c6`. Do not claim that harness issue was a source transport defect. [Exact direct R06 Node22/24 run #37806504626](https://github.com/reallaksh19/3D_Converters/actions/runs/37806504626) passed the corrected test.

The returned `acknowledgedBytes` is **transport receipt accounting only**, not independently verified JSON parsing/consumed-byte progress. `complete:false`, `engineeringReady:false`, `rightsBasis:SOURCE_TRANSPORT_ONLY` are enforced. U03's opt-in explicit consumption mode is defined below; U04 now handles failed page-job termination; R07 still owns cross-job cancellation, stale sessions, retry and full lifecycle disposal. This module does not integrate R05 parsing into a Worker, grant output rights, replace actual Preview/Weight controllers or prove R18 populated 30/90MB browser responsiveness.

## U03 actual Worker-consumed-source progress (distinct from transport ACK)

`transferBoundedSourcePages({...,onConsumed})` retains U02 ACK-only transport semantics when no progress observer is supplied. When a **synchronous** `onConsumed` observer is supplied, a matching `SOURCE_ACK` establishes byte transport delivery **but never updates consumed-source progress or releases another page**. Only a later separate `SOURCE_CONSUMED` message from the *platform-trusted isolated Worker*, bound to the exact job, caller sourceRefId, original SHA/revision and page offset, and reporting exact monotonic cumulative `consumedBytes`, permits advance. A missing consumed report fails typed `WORKER_CONSUME_TIMEOUT`, invalid count/source/protocol returns `WORKER_PROTOCOL`; the sender still cannot read a second source page while the first is unconsumed. In consumption mode, the returned transport receipt exposes `workerConsumedBytes` separately from `acknowledgedBytes`. Neither field is a parsed R05 index result; `complete:false` and `engineeringReady:false` remain mandatory.

[Independent real-Worker U03 tests](./consumed-source-progress.test.mjs) and [test-only source-byte consumer fixture](./consumed-source-fixture.mjs) verify that the isolated Node worker **actually iterates every byte** and produces a page checksum independently recomputed from original test bytes. The first test uses a release gate: the worker sends ACK before processing and waits for the test's explicit `CONSUME_NOW`, proving ACK alone does not advance progress; cumulative reports are 8192 → 16384 → 24576 → 24583 original bytes, source pages never overlap. A second test sends ACK but performs no processing: progress stays zero, only one source range is read, and `WORKER_CONSUME_TIMEOUT` occurs. A third deliberately lies about consumed offset and gets `WORKER_PROTOCOL` with no progress. Test-first commit `212540f897c2b9b00fc087dde33ebc31eab1cc69` was a **real semantic RED** against the prior U02 ACK-only producer (Node22/24 #37807529366); production bridge `76de00de4c1230bd1824948dc84599783f8c1bd1` passed the direct Node22/24 job #37807679306.

**Boundary:** This proves the truthful **R06 transport/consumption progress protocol** against a real source-byte-consuming test Worker, **not yet R05's JSON parser running inside a production Worker**, not source-to-CII golden output, and not a browser 30/90MB responsiveness/heap target. The trusted Worker application's true parser remains responsible for emitting `SOURCE_CONSUMED` **only after consuming source bytes**; a deliberately malicious Worker in the trusted factory could lie. R10/adoption and R18 retain those independent release gates.

## U04 fail-closed fault closure (native Worker tests)

**Independent RED:** native Worker fault matrix [worker-failure.test.mjs](./worker-failure.test.mjs) with a genuine [WorkerThreads fixture](./worker-failure-fixture.mjs) was committed before production at `10a13b23c6fd18ee1d8c794f901064644d40735b`. Hosted [U04 RED #37808913186](https://github.com/reallaksh19/3D_Converters/actions/runs/37808913186) Node22/24 reproduced two source defects: a native Worker exit before READY waited 5 seconds and returned `WORKER_UNAVAILABLE` instead of immediate `WORKER_FAILED`, and wrong READY/ACK or a throwing consumption observer rejected **without terminating the Worker**. Two crash-after-start tests already passed RED, so they were NOT claimed as newly repaired defects.

**Production GREEN:** `required-worker.mjs` now listens to native Worker `exit` before READY; failed admission awaits termination while successful admission leaves Worker available for the R03 job. `bounded-source-transfer.mjs` awaits termination on any failed source read, ACK/consumption protocol, observer callback, worker crash or page timeout. Error code remains typed; a failed job cannot return a successful receipt, silently execute inline or keep a native source Worker running. Tests independently check Worker `threadId === -1` on rejection. R06 does **not** implement R07 cross-job cancel, reuse/epoch or retry.

**Additional negatives:** real Worker without ACK, a duplicate ACK before consumption and `SOURCE_CONSUMED` before `SOURCE_ACK` all fail closed on the first page with zero accepted consumption and an awaited terminated Worker. [Dedicated exact tested source head #37814361124](https://github.com/reallaksh19/3D_Converters/actions/runs/37814361124) passed Node22/24 before these additional negative tests. The final exact-head runs are authoritative after this README checkpoint, not any older SHA.
