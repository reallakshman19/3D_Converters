## Actual browser path

`runXmlCii2019WorkflowService` freezes the exact post-Preview engine-input XML, effective support configuration, staged JSON, invocation options and original CII SHA-256. The existing Final Weight Review popup is augmented with a **separate Source-backed XML edit mode**; all previous direct-CII controls, nearest suggestions, reference/error calculations and fullscreen actions remain separate.

The R2 mode:
1. Pins the original XML/CII bytes, configuration, staged JSON, source name and run identity. Rejects missing/unknown effective flags.
2. Replays **the original engine XML directly** through the existing `runXmlCii2019StandaloneEngineJob` and bundled Pyodide runtime, using original arguments with `outputMode:'cii-only'`. Requires original CII string byte parity and SHA-256. It never passes amended XML through the JavaScript enrichment stage again.
3. Parses all 15 IEL CII pointer fields, CONTROL counts and auxiliary records. Independently reparses RIGID weights and emitted ELEMENT OD/length against the frozen original CII evidence.
4. Applies strict **direct-edge-only source selection**: same original branch, FROM/TO, coordinates, unique physical ComponentRefNo, writer-selected `Node/Weight`, pinned weight scale, no stale/new overrides. Negative renumbering, shortened/collapsed edges, ambiguous ownership and a second potentially dependent emitted RIGID remain **HOLD**. A verified writer-selected node alone is not physical-mass approval.
5. Requires separate positive **physical-owner allocation authorization** and **individual weight-change approval**; zero requires additional confirmation. Catalog suggestions never implicitly approve edits.
6. Uses the immutable, property-descriptor-driven XML token patcher, currently registering only `Node/Weight`; no global replacement or full XML reserialization. Reports original/revised SHA-256, the one changed field and zero unrelated XML differences.
7. Invokes the same browser/Pyodide converter with revised exact engine-input XML. The verifier reconciles final RIGID weights through source-linked ELEMENT branch/FROM/TO/geometry/OD rather than relying on unchanged 1-based RIGID pointers, and refuses unexpected ELEMENT, RIGID type, any other auxiliary record or 15-slot pointer changes.
8. Makes revised EnrichedXML, re-extracted CII and change-audit downloadable **only** when the full transaction passes. Original XML/CII remain immutable. A repeated identical Apply reuses its verified result without a second edit; other changes require a fresh session.

The transaction engine can validate multiple text edits atomically, but the production R2 UI intentionally supports only one approved Weight per Apply. This does not imply batch-edit release approval.
