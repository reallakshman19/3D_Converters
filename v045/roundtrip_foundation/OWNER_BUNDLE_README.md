The names above are **examples only**; `run-custody.json` must list **every actual dependency used during that exact run**, not an imposed set of four masters. Its `requiredUpstreamAssetRoles` and `upstreamAssets` lists must agree exactly. The native Python converter often receives upstream master effects already applied in the frozen engine-input XML and config. Do not fabricate a master, omit a required import, or silently substitute a worksheet selection.

## Evidence boundary

All original-run dependency roles must be recorded from retained evidence. An attestation alone does **not** independently prove that a claimed original CII or master belongs to the historical run; verify against independent run receipts where available. Reports identify this limit explicitly. Converter snapshots pin the entrypoint and its statically imported local Python dependency closure, not only an arbitrary manually selected list of module filenames.

The CI tests create their own synthetic source/master/CII files in isolated temporary directories to verify the intake and fail-closed behavior. They are **not** an authentic Owner run.
