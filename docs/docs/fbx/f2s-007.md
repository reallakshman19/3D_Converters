# F2S-007 — Bounded-memory deterministic review execution

## Status

F2S-007 adds an opt-in bounded-memory execution strategy for the accepted FBX mapping-review bundle and decision-fragment assembly chain.

The in-memory F2S-006 implementation remains the semantic and complete-byte oracle. No FBX contract, parser, source-graph, mapping, port, connectivity, topology, writer, registry, viewer, or downstream authority is changed.

Hosted GitHub Actions execution is unavailable because repository Actions credits are exhausted. The Owner issued an F2S-007-specific decision to continue with local qualification. That decision waives only hosted execution while credits are unavailable; all byte-parity, resource, cleanup, scope, and Owner-review gates remain mandatory.

## Bounded CLI paths

Bundle generation:

```bash
node scripts/fbx/build-mapping-review-bundle.mjs \
  worklist.json \
  review-bundle \
  --max-items 1000 \
  --bounded-memory \
  --sort-run-items 5000 \
  --input-chunk-bytes 65536
```

Fragment assembly:

```bash
node scripts/fbx/assemble-mapping-decision-fragments.mjs \
  worklist.json \
  review-bundle/manifest.json \
  fragments/*.json \
  --output decision-set.json \
  --bounded-memory \
  --sort-run-items 5000 \
  --input-chunk-bytes 65536
```

Execution options affect only temporary run sizing and incremental input reads. They cannot affect canonical output bytes, identifiers, ordering, shard boundaries, coverage, or validation outcomes. Duplicate execution options are rejected as ambiguous input.

## Execution model

The bounded bundle path:

1. incrementally reads the top-level worklist and streams `workItems` and `retainedEvidence`;
2. validates each closed nested record using the accepted worklist validator;
3. reconstructs the accepted worklist payload hash in original insertion order;
4. externally sorts work items by the accepted text comparator;
5. externally sorts identity records to detect global duplicates and governed/retained overlap across run boundaries;
6. creates one shard-sized object at a time;
7. calculates accepted shard and bundle identifiers;
8. stages JSON and CSV outputs under a private workspace;
9. removes an existing output directory only with non-recursive `rmdir()` after proving it is an empty directory;
10. renames the staged directory to the final name and fails closed on `ENOTEMPTY`, `EEXIST`, or target-type changes;
11. removes all temporary state in a `finally` path.

The bounded assembly path:

1. incrementally validates and sorts the accepted worklist;
2. verifies the bundle and reconstructs every expected shard from the worklist;
3. indexes fragment files independently of input order;
4. validates one fragment and one shard-sized decision set at a time;
5. verifies exact decision coverage and promotion identity;
6. spools decisions in accepted `workItemId` order;
7. calculates and writes canonical decision-set bytes in two passes;
8. publishes the final file by exclusive same-filesystem hard-link creation;
9. treats staged-link removal as post-commit cleanup owned by the private-workspace `finally` path;
10. removes all temporary state in a `finally` path.

The implementation never recursively deletes a publication target. A file target appearing after initial validation causes exclusive link creation to fail with `EEXIST`. A non-empty directory or changed target type appearing after directory preparation causes publication to fail without deleting the external target.

SIGINT and SIGTERM are trapped while a private workspace is active. Incremental reads, sort runs, merges, shard generation, fragment indexing, and decision spooling check the cancellation state. Cancellation before publication removes the private workspace and publishes no final artifact.
