## Status

`PARTIAL — BLOCKED_WASM_REBUILD`

The source implementation, strict executable v2 schema, explicit v2-to-v1 compatibility boundary, deterministic all-category fixture generator and proof suite are implemented on the mission branch. Publication is not complete until the committed parser WASM is rebuilt from the updated C bridge and the full suite passes against that exact binary.

## Authority decisions

- `FbxSourceGraph.v2` is the authoritative parser artifact.
- Only retained DOM-backed FBX elements are source objects; synthetic ufbx elements without source DOM records are excluded from source-object authority.
- Exact retained DOM class, subtype and serialized source name are kept separately from the ufbx-decoded display name.
- Symbolic and numeric ufbx element types remain paired by the Draft 2020-12 schema.
- Unknown retained source objects are preserved as `UNKNOWN` with numeric type evidence and `unresolved-unknown`; they are never silently discarded or represented solely as `OTHER`.
- Existing mapping, port, connectivity, transform and StagedJSON writer modules remain unchanged.
- `conversion.js` invokes a named pure `FbxSourceGraph.v2` to `FbxSourceGraph.v1` projection before the unchanged F2S-001 mapping boundary.
- The v1 projection reuses the exact accepted F2S-001 comparator and canonicalization rules, including numeric-string digit-length ordering and code-point comparison without locale collation.
- The v1 projection maps non-F2S-001 source categories to legacy `OTHER` only inside the explicitly named compatibility artifact; v2 remains authoritative.
- Geometry vertices, NURBS control points and other source-order-sensitive arrays are not reordered.
- Canonicalization stable-sorts evidence lists without deduplicating repeated claims. Multiplicity is authoritative evidence.

## Governed `objectPropertyPath` disposition

`objectPropertyPath` is governed as `null` for the pinned `ufbx v0.18.0` boundary. The public retained-DOM node contains only its own name, values and children; it has no parent pointer, and the public scene contract exposes no retained-DOM root from which a truthful ancestry path can be reconstructed. A synthetic `/Objects/...` locator would therefore be invented evidence, not preserved source evidence.

The v2 schema requires `objectPropertyPath` to be exactly `null`, and schema-negative tests reject invented paths. This disposition must be revisited if a future Owner-approved parser boundary exposes stable DOM ancestry.

## Strict executable schema

`contracts/fbx/fbx-source-graph.v2.schema.json` is a closed Draft 2020-12 contract for every authoritative record shape:

```text
file
documentMetadata
globalSettings
sourceObjects and customProperties
occurrences
mesh and NURBS geometry ownership
hierarchyEdges
connectionEdges
warnings
unsupportedRecords
unresolvedReferences
duplicateSourceObjectIds
```

The pinned symbolic/numeric enum mapping is isolated in `contracts/fbx/fbx-element-type-pair.v2.schema.json` and registered through `contracts/fbx/fbx-type-evidence.v2.schema.json`.

`tests/fbx/test-source-graph-v2.mjs` executes Python `jsonschema.Draft202012Validator`, validates real parser output, and supplies negative cases for missing fields, wrong types, unknown properties, dispositions, geometry ownership, hierarchy/connection relationships, unknown/unresolved evidence, object-path disposition and symbolic/numeric pairings.

## Schema validator environment

The executable schema test does not rely on Ubuntu's system `python3-jsonschema` package. Ubuntu 24.04 provides an older release that predates the `referencing.Registry` integration used by this proof.

The project declares the required validator packages in:

```text
scripts/fbx/schema-validator-requirements.txt
```

Create an isolated environment before local certification:

```bash
python3 -m venv .venv-fbx-schema
.venv-fbx-schema/bin/python -m pip install \
  --disable-pip-version-check \
  --requirement scripts/fbx/schema-validator-requirements.txt
export FBX_SCHEMA_PYTHON=.venv-fbx-schema/bin/python
```

`tests/fbx/test-source-graph-v2.mjs` uses `FBX_SCHEMA_PYTHON` when set and otherwise falls back to `python3`. The FBX workflow provisions the same project-local environment from the checked-in requirements file.
