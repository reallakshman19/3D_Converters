# F2S-007 — Bounded-memory deterministic review execution

## Status

F2S-007 adds an opt-in bounded-memory execution strategy for the accepted FBX mapping-review bundle and decision-fragment assembly chain.

The in-memory F2S-006 implementation remains the semantic and complete-byte oracle. No FBX contract, parser, source-graph, mapping, port, connectivity, topology, writer, registry, viewer, or downstream authority is changed.

Hosted GitHub Actions execution is currently unavailable because repository Actions credits are exhausted. The Owner issued an F2S-007-specific decision to continue with local qualification. That decision waives only hosted execution while credits are unavailable; all byte-parity, resource, cleanup, scope, and Owner-review gates remain mandatory.

## Bounded CLI paths

Bundle generation:

```bash
node scripts/fbx/build-mapping-review-bundle.mjs \
  worklist.json \
  review-bundle \
  --max-items 1000 \
  --bounded-memory \
  --sort-run-items 5000 \
  --input-chunk-bytes 65536
```

Fragment assembly:

```bash
node scripts/fbx/assemble-mapping-decision-fragments.mjs \
  worklist.json \
  review-bundle/manifest.json \
  fragments/*.json \
  --output decision-set.json \
  --bounded-memory \
  --sort-run-items 5000 \
  --input-chunk-bytes 65536
```

The execution options affect only temporary run sizing and incremental input reads. They must not affect canonical output bytes, identifiers, ordering, shard boundaries, coverage, or validation outcomes.

## Execution model

The bounded bundle path:

1. incrementally reads the top-level worklist and streams `workItems` and `retainedEvidence`;
2. validates each closed nested record using the accepted worklist validator;
3. reconstructs the accepted worklist payload hash in original insertion order;
4. externally sorts work items by the accepted text comparator;
5. externally sorts identity records to detect global duplicates and governed/retained overlap across run boundaries;
6. creates one shard-sized object at a time;
7. calculates accepted shard and bundle identifiers;
8. stages JSON and CSV outputs under a private workspace;
9. publishes the verified directory by final-name rename;
10. removes all temporary state in a `finally` path.

The bounded assembly path:

1. incrementally validates and sorts the accepted worklist;
2. verifies the bundle and reconstructs every expected shard from the worklist;
3. indexes fragment files independently of input order;
4. validates one fragment and one shard-sized decision set at a time;
5. verifies exact decision coverage and promotion identity;
6. spools decisions in accepted `workItemId` order;
7. calculates and writes canonical decision-set bytes in two passes;
8. publishes by final-name rename only after all gates pass;
9. removes all temporary state in a `finally` path.

SIGINT and SIGTERM are trapped while a private workspace is active. Incremental reads, sort runs, merges, shard generation, fragment indexing, and decision spooling check the cancellation state. Cancellation before the atomic rename removes the private workspace and publishes no final artifact.

## Formal L2 and L3 qualification

Run from a clean checkout of the exact PR head on a Linux machine with sufficient temporary disk space:

```bash
F2S007_SCALE_LEVELS=L2,L3 \
F2S007_SCALE_RUNS=3 \
F2S007_MAX_ITEMS_PER_SHARD=1000 \
F2S007_SORT_RUN_ITEMS=5000 \
F2S007_INPUT_CHUNK_BYTES=65536 \
F2S007_REPORT_PATH=/tmp/f2s007-l2-l3-report.json \
node tests/fbx/test-review-resource-bounds.mjs
```

The formal command:

- generates 100,000-item and 1,000,000-item canonical worklists at runtime;
- commits no generated corpus;
- runs reference bundle and assembly at L2;
- runs bounded bundle and assembly three times at L2 and L3;
- requires complete-byte L2 parity for manifests, shard JSON, shard CSV, and decision sets;
- measures wall and CPU duration, peak RSS, peak JavaScript heap, monitored disk growth, kernel read/write bytes, and file-descriptor peak;
- requires L3 peak RSS no greater than 1.5 GiB;
- requires L2-to-L3 peak-RSS growth no greater than 2.5 times;
- verifies zero mission workspace residue after each operation;
- removes generated data unless `F2S007_KEEP_SCALE_OUTPUT=1` is explicitly set.

The report contains median and worst wall duration across the requested repetitions. `/proc/self/io` and `/proc/self/fd` measurements are available on Linux; unsupported platforms record those fields as `null` or zero and are not suitable for formal qualification.
