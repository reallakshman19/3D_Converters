# F2S-003 — Mapping-gated FBX component families

## Status

```text
Issue: #261
Accepted dependency: bfe387e190cfa6251d73c1f84471cf0251dc6dfb
Implementation branch: agent/f2s-003-mapping-gated-families
Scope: FBX mapping → native StagedJSON only
```

F2S-003 extends the accepted PIPE-only path to explicitly mapped `ELBOW`, `TEE`, `REDUCER`, `FLANGE`, and `VALVE` entries. It does not classify FBX objects from names, hierarchy, geometry shape, or proximity.

## Authority chain

```text
FbxSourceGraph.v2
→ FbxStagedMapping.v2
→ closed family validation
→ transform-governed mapped ports
→ explicit symmetric connectivity
→ native StagedJSON
```

`FbxSourceGraph.v2` remains the source-evidence authority. The v1 compatibility projection is still executed as a regression gate, but F2S-003 mapping, ownership, port resolution, and ledger generation use the original v2 graph.

## Mapping schema

The executable contract is:

```text
contracts/fbx/fbx-staged-mapping.v2.schema.json
```

Every promoted entry declares:

```text
mappingEntryId
logicalComponentId
sourceModelObjectId
sourceOccurrenceId
sourceGeometryObjectIds
componentType
scopeDisposition = promote
ports
engineering
```

Every port declares:

```text
portId
role
authority = mesh-vertex | nurbs-control-point
geometryObjectId
vertexIndex | controlPointIndex
direction.authority = world-vector
direction.vector
connections
```

Port positions are resolved from the accepted geometry resource and occurrence transform. Explicit world-direction vectors provide orientation evidence; they cannot provide coordinate authority.

## Family contracts

| Mapping family | Native type | Port roles | Required engineering evidence |
|---|---|---|---|
| PIPE | PIPE | A, L | none |
| ELBOW | ELBO | A, L | bend radius, bend angle, bend-plane normal |
| TEE | TEE | A, L, P | run diameter, branch diameter |
| REDUCER | REDU | A, L | large/small diameters, governed end identities, concentric/eccentric policy |
| FLANGE | FLAN | A, L | nominal diameter, thickness, explicit flange type |
| VALVE | VALV | A, L | nominal diameter, face-to-face length, explicit valve type |

The resolver rejects contradictory evidence:

- straight-family A/L directions must agree with the resolved span;
- flange thickness and valve face-to-face length must equal the resolved A/L span;
- elbow radius and angle must agree with the resolved port chord;
- TEE `P` must lie on the resolved A/L run span;
- eccentric reducer direction must be explicit and perpendicular to the run axis.

## TEE branch representation

A mapped TEE uses existing native topology semantics without changing downstream modules:

```text
TEE.AP0S / LPOS  → run ports A / L
TEE.POS          → branch port P
TEE.CREF         → generated mapped branch name
branch.HREF/TPREF → reciprocal TEE logical component identity
```

The `P` connection is treated as a governed route cut. Removing these governed branch links must leave deterministic linear acyclic route segments. Cycles, P-to-P links, branch reconnection, or ambiguous nonlinear runs are blocked.

## Connectivity policy

Connectivity exists only through reciprocal mapping claims. Validation rejects:

- same-component self-links;
- dangling links;
- asymmetric links;
- multiple claims on one port;
- directionally inconsistent connections;
- TEE branch links that reconnect one route segment;
- coordinate coincidence without an explicit link.

Coordinates verify mapped links; they never create them.

## Compatibility

`FbxStagedMapping.v1` remains accepted by the preserved PIPE path. Its normalized entries, mapping ledger, branch/component shape, and staged bytes are unchanged. F2S-003 dispatches v1 and v2 through separate resolver, connectivity, and writer paths behind one conversion boundary.
