# F2S-005 — Governed FBX mapping worklist and decision compiler

## Purpose

F2S-005 adds a deterministic human-review boundary between
`FbxSourceGraph.v2` and the existing authoritative `FbxStagedMapping.v2`
manifest. It does not classify components, generate ports, infer connectivity,
or create engineering values.

The governed flow is:

```text
exact FBX bytes
→ accepted parser/WASM and FbxSourceGraph.v2
→ FbxMappingWorklist.v1
→ explicit FbxMappingDecisionSet.v1
→ existing FbxStagedMapping.v2 validation
→ canonical FbxStagedMapping.v2
→ optional existing F2S-004 package builder
```

## Worklist authority

The structural scope policy is fixed as:

```text
ufbxElementType = NODE
sourceRecordDisposition = supported-occurrence
identity join = occurrence.sourceModelObjectId
```

Every canonical occurrence meeting that policy becomes exactly one work item.
All other source objects remain in `retainedEvidence` as non-occurrence trace
evidence.

Worklist generation rejects duplicate source-object, occurrence, and geometry
identities. Every occurrence must resolve exactly one source model, and every
governed geometry reference must resolve once with explicit occurrence
ownership. Ambiguous or dangling joins terminate as
`BLOCKED_WORKLIST_SOURCE_GRAPH_BINDING` rather than being collapsed or omitted.

Work items preserve:

- exact source model, occurrence and geometry identities;
- ufbx element and node-attribute type evidence;
- DOM class, subtype, source name and display name as explicitly
  `NON_AUTHORITATIVE` evidence;
- geometry kind and source-governed mesh-vertex or NURBS-control-point count;
- review state `PENDING`.

They contain no `componentType`, ports, connection claims, directions,
engineering values, dimensional values, family subtype, proximity result, or
geometry-based proposal.

`workItemId` is a SHA-256-derived identity over the canonical work-item
evidence. `worklistId` is SHA-256 over the canonical worklist payload excluding
only `worklistId` itself.

## Closed runtime contract

`mapping-worklist-contract.js` enforces the same closed information model at the
production runtime boundary. It validates the complete nested shape of:

```text
source
parser
sourceGraph
scopePolicy
workItems and their evidence
retainedEvidence
```

Malformed or unexpected nested fields terminate as
`BLOCKED_WORKLIST_CONTRACT`. They do not reach shared binding functions as
uncontrolled JavaScript errors.

## Decision authority

A decision set binds to one exact worklist and source-graph digest. Every work
item must receive exactly one explicit decision:

```text
exclude-with-reason
promote
```

An exclusion requires a non-empty substantive reason. Placeholder sentinels
such as `TBD`, `TODO`, `PLACEHOLDER`, and `DEFAULT` are rejected by both the JSON
Schema and runtime decision validator.

A promotion embeds one complete candidate entry using the existing
`FbxStagedMapping.v2` entry contract.

The compiler rejects:

- missing, duplicate or unknown work-item decisions;
- another worklist or source-graph binding;
- altered source-model identity;
- altered source-occurrence identity;
- altered geometry ownership;
- multiple work items for one source model, which the current mapping contract
  cannot represent as independent dispositions;
- placeholder-bearing decisions and unbound coordinate claims.

After those gates, the compiler delegates to the existing production:

```text
validateMappingManifest()
resolveEntryPortsV2()
validateConnectivityV2()
```

No family, port, connectivity or engineering rule is duplicated.

## Contracts

```text
contracts/fbx/fbx-mapping-worklist.v1.schema.json
contracts/fbx/fbx-mapping-decision-set.v1.schema.json
```

The decision-set schema references the existing closed
`FbxStagedMapping.v2#/$defs/entry` definition for promoted entries.

## Commands

Generate a worklist:

```bash
node scripts/fbx/build-mapping-worklist.mjs \
  <source.fbx> <output.worklist.json>
```

Compile completed decisions:

```bash
node scripts/fbx/compile-mapping-decisions.mjs \
  <source.fbx> <worklist.json> <decisions.json> <output.fbxmap.json>
```

Package the validated compiled mapping through the existing F2S-004 authority:

```bash
node scripts/fbx/build-mapping-package.mjs \
  <source.fbx> <compiled.fbxmap.json> <output.package.json>
```

The compiler writes no output when any binding, coverage, conflict, mapping,
port or connectivity gate fails.

## Controlled classifications

```text
BLOCKED_WORKLIST_SOURCE_BINDING
BLOCKED_WORKLIST_PARSER_BINDING
BLOCKED_WORKLIST_SOURCE_GRAPH_BINDING
BLOCKED_WORKLIST_CONTRACT
BLOCKED_DECISION_BINDING
BLOCKED_DECISION_COVERAGE
BLOCKED_DECISION_CONFLICT
BLOCKED_MAPPING
```

Existing `BLOCKED_MAPPING` diagnostics remain unchanged after the authoring
boundary hands the candidate manifest to the accepted mapping authorities.

## Existing-contract limitation

The current `FbxStagedMapping.v2` authority requires at least one promoted
entry. Therefore a complete all-exclusion decision set is fully reviewed but
cannot be emitted as a valid mapping; it terminates with the existing
`BLOCKED_MAPPING mapping entries are required.` diagnostic. F2S-005 does not
weaken or amend that authority.

## Determinism

Canonical output is independent of source-object, occurrence, geometry,
decision, promotion and exclusion insertion order. No current time, user,
machine path, temporary path, locale, random value, worker schedule, name
classification, proximity rule or ray-shoot result enters the canonical
boundary.
