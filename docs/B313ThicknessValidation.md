## 4. Validation architecture

Three independent artifacts are used:

1. **Production JavaScript** — the module consumed by other application code.
2. **Frozen golden benchmark data** — expected numerical results, ratios, and failure codes are recorded as data, not calculated inside the production module.
3. **Independent Python arithmetic oracle** — reads the same benchmark inputs but does not import or execute production JavaScript.

This prevents a unit test from passing merely because its expected result is generated by the same implementation being tested.

## 8. Mill-tolerance validation

The tolerance subsystem is validated independently from the pressure equation.

For a required minimum thickness of exactly `10.000 mm`:

```text
12.5% basis:
required nominal = 10 / (1 - 0.125)
                 = 11.428571428571429 mm
minimum as manufactured = 11.428571428571429 * 0.875
                        = 10.000000000000000 mm

Equivalent absolute basis:
absolute deduction = 1.428571428571429 mm
required nominal   = 10 + 1.428571428571429
                   = 11.428571428571429 mm
minimum as manufactured = 11.428571428571429 - 1.428571428571429
                        = 10.000000000000000 mm
```

This proves both representations converge on the same adequacy invariant when they represent the same physical deduction.

## 9. Unit parity

- `B313-V007` validates `psi`/`in` equivalence to the SI baseline.
- absolute manufacturing tolerance is tested in both `mm` and `in`.
- `barg` and `psig` are accepted as pressure-difference units; no atmospheric offset is added.
- the A106 Grade B benchmark validates `barg` versus `ksi` ratio normalization.

## 10. Provided-wall and wall-selection tests

The automated suite verifies:

- provided nominal wall exactly at the calculated requirement -> `PASS`;
- a nominal wall 0.01 mm below -> `FAIL`;
- PASS/FAIL uses minimum as-manufactured wall after tolerance deduction;
- the wall selector chooses the thinnest adequate candidate;
- no adequate candidate returns `NO_ADEQUATE_NOMINAL_WALL`.

## 11. Property / metamorphic testing

The core Node suite runs **1,000 deterministic seeded cases** and checks:

- increasing design pressure does not decrease required nominal thickness;
- increasing allowable stress does not increase required nominal thickness;
- increasing corrosion allowance increases required nominal thickness;
- increasing negative percentage manufacturing tolerance does not decrease required nominal thickness.

Seeded generation makes this regression exactly repeatable.
