## 4. Validation architecture

Three independent artifacts are used:

1. **Production JavaScript** — the module consumed by other application code.
2. **Frozen golden benchmark JSON** — expected results and expected failure codes are recorded as data, not calculated inside the test.
3. **Independent Python arithmetic oracle** — reads the same benchmark inputs but does not import or execute production JavaScript.

This prevents a unit test from passing merely because its expected result is generated by the same implementation being tested.

## 7. Mill-tolerance validation

The tolerance subsystem is validated independently from the pressure equation.

For a required minimum thickness of exactly `10.000 mm`:

### Percentage case

```text
negative tolerance = 12.5%
required nominal = 10 / (1 - 0.125)
                 = 11.428571428571429 mm
minimum as manufactured
                 = 11.428571428571429 * 0.875
                 = 10.000000000000000 mm
```

### Equivalent absolute case

```text
absolute deduction = 1.428571428571429 mm
required nominal   = 10 + 1.428571428571429
                   = 11.428571428571429 mm
minimum as manufactured
                   = 11.428571428571429 - 1.428571428571429
                   = 10.000000000000000 mm
```

This proves both tolerance representations converge on the same adequacy invariant when they represent the same physical deduction.

## 8. Unit parity

`B313-V007` uses `psi` and `in` inputs physically equivalent to the SI values in `B313-V001`. Both must reproduce the same normalized MPa/mm calculation within benchmark tolerance.

Absolute manufacturing tolerance is also tested in both `mm` and `in`.

## 9. Provided-wall boundary tests

The automated suite verifies:

- provided nominal wall exactly equal to the calculated required nominal wall -> `PASS`;
- a nominal wall 0.01 mm below that boundary -> `FAIL`;
- PASS/FAIL uses the **minimum as-manufactured wall** after the declared tolerance deduction.

## 10. Nominal-wall selection tests

A candidate set is supplied in deliberately unsorted adequacy order. The selector must choose the thinnest candidate whose minimum as-manufactured wall meets the required minimum.

A separate test supplies only inadequate candidates and requires `NO_ADEQUATE_NOMINAL_WALL`.

## 11. Property / metamorphic testing

The Node suite runs **1,000 deterministic seeded cases**. For each valid generated case it checks:

- increasing design pressure does not decrease required nominal thickness;
- increasing allowable stress does not increase required nominal thickness;
- increasing corrosion allowance increases required nominal thickness;
- increasing negative percentage manufacturing tolerance does not decrease required nominal thickness.

Seeded generation makes this regression exactly repeatable.
