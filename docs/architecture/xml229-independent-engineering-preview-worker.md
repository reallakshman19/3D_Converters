The parent original-blob-gcpw Worker proves the original Blob SHA, creates a SHA-256 InputBasis from current original XML/JSON and four master mappings and independently enumerates physical owner census. It now delegates only the heavyweight xmlCiiDryRunPreview call to xml229-independent-engineering-preview-worker.mjs (a real separate module Worker) through xml229-independent-engineering-preview-client.mjs.

The new Preview child clones a Blob, independently verifies original JSON SHA-256, decodes it with fatal UTF-8, runs the exact existing Preview calculation in a disposable config view, and posts the computed rows with requestId + basisId + sourceId + sourceGenerationId + originalJsonSha256. It does not trust row count alone for physical acceptance; the existing independently enumerated census must still match.

The child does not receive Match-1/Final decision commands. The transport does not receive native converter or Output/Run authority. Only original GC-PW Worker keeps the separately attested review service. Original client #280 watchdog/cancellation remains in effect; parent Worker AbortController also terminates the child upon explicit Cancel, and child replies are late-response fenced.

Potential performance/memory risk: the original Blob and full Preview config are structured-cloned to a child Worker, and original JSON is decoded again. Blob clone may share backing storage in browsers but must not be assumed zero-copy; compare measured memory with base. The child cannot currently issue CPU mid-stage heartbeats because dryrun is synchronous; #280 parent-stage deadline and the independent child deadline detect stalls and abort, but cannot accelerate an expensive algorithm. Staged index sharing in #282 addresses one measured-by-code repeated JSON-index construction; no Owner-private speedup is yet demonstrated.
